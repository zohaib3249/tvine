# AGENTS.md: building with Tvine

This project uses **Tvine**: Django for TypeScript, with Next.js pages, and a UI that AI agents can read and drive.
The npm package is `tvinejs`, but you always import it and run it as `tvine`.
Read this file before you write any code. It covers the layout, the commands, copy-paste recipes and the rules.

## Mental model

- **One process.** `tvine dev` runs the backend (**Warp**) and Next.js (**Weft**) on one port.
- **Warp is Django.** Apps, `defineModel` + ORM, migrations, `installedApps`, `urls.ts`, admin, auth, middleware,
  tasks (Celery-like), and a test client. Django names are kept, in camelCase (`listDisplay`, `getQueryset`).
- **Every action is four things at once.** Each function or method in `apps/<app>/views.ts` is an *action* with
  id `<app>.<name>`:
  1. `api.<app>.<name>(params)` for pages
  2. `POST /tvine/api/<app>.<name>`
  3. the MCP tool `<app>_<name>` at `/mcp`
  4. an optional REST path in `urls.ts`

  All four run the same pipeline: zod validation, permissions, rate limit, one DB transaction.
- **Weft pages are agent-readable.** `<Page>`, widgets and plain `<form>/<button>/<input>` register in a control
  tree. An agent gets the page as JSON (`x-tvine: 1` header, or the MCP `read_page` tool) and drives it with `do`
  and `ui`.

## Project layout

```
config/
  settings/base.ts      shared settings: installedApps, middleware, mcp, db, auth (Django settings.py)
  settings/dev.ts       base + debug + local hosts (used by tvine dev, migrate, shell, test)
  settings/prod.ts      base + secrets from the env (used by tvine start / NODE_ENV=production)
  settings/local.ts     optional, git-ignored, merged over dev.ts (copy local.example.ts)
  urls.ts               root URLconf: urlpatterns = [path(...), include('<app>.urls')]
  tasks.ts              worker queues + beatSchedule (cron) for `tvine worker --beat`
  middleware/           your HTTP middleware; export from index.ts, enable as 'config.middleware.<name>'
apps/<app>/
  models.ts             defineModel(...) models
  views.ts              actions: defineAction(...) and ListView/DetailView/... classes with @action
  urls.ts               appName + urlpatterns (REST paths, optional)
  admin.ts              admin.site.register(Model, ModelAdmin subclass)
  tasks.ts              background jobs: defineTask(...)            (optional)
  rules.ts / serializers.ts / middleware.ts / hooks.ts               (optional)
  migrations/           generated by makemigrations; commit them; never hand-edit
  tests/<app>.test.ts   vitest
app/                    Next.js App Router pages (layout.tsx wraps everything in <WeftRoot>)
tvine-api.d.ts          generated types for api.* (tvine generate; tvine dev regenerates it on save)
.env                    dev only: TVINE_SECRET, DATABASE_URL (git-ignored)
.mcp.json               points Claude Code at http://localhost:3000/mcp
```

`TVINE_SETTINGS=config/settings/prod` (or `--settings config/settings/prod`) picks the settings module.
The default is `prod` when `NODE_ENV=production`, otherwise `dev` + `local.ts`.

## Commands

Run them through the project: `pnpm tvine <cmd>` (or `npx tvine <cmd>`). Never `npx tvinejs` inside a project.

| Command | What it does |
|---|---|
| `tvine dev [--port 3000]` | dev server: backend + Next + HMR. A busy port moves to the next free one; it prints the URL |
| `tvine startapp <name>` | `apps/<name>/` stubs; adds it to `installedApps` and `config/urls.ts` |
| `tvine makemigrations [app]` | writes `apps/<app>/migrations/000N_*.ts` from model changes |
| `tvine migrate [app [target\|zero]]` | applies migrations (or rolls back to a target) |
| `tvine createsuperuser` | admin login (`--noinput` reads `TVINE_SUPERUSER_USERNAME/_EMAIL/_PASSWORD`) |
| `tvine check` | settings + actions + migrations + the frontend/DB boundary. **Run it after every change** |
| `tvine test` | vitest run |
| `tvine shell` | Node REPL with settings loaded and every model by name |
| `tvine show_urls` | urls.ts routes: pattern, methods, name, action |
| `tvine routes` | every action (the manifest) |
| `tvine generate` | writes `tvine-api.d.ts` (types for `api.*`) |
| `tvine worker [--beat]` | runs background tasks (and cron with `--beat`) |
| `tvine build` / `tvine start` | production build / serve (`start` needs `TVINE_SECRET`, `TVINE_ALLOWED_HOSTS`) |
| `tvine docs --ai` | prints this guide |

## Recipes

All code below uses an app named `blog`. Create it first with `pnpm tvine startapp blog`.

### 1. A model + migration

```ts
// apps/blog/models.ts
import { defineModel, field, type Infer } from 'tvine'

export const Post = defineModel('post', {
  id: field.id(),
  title: field.text({ searchable: true }),
  body: field.text({ default: '' }),
  published: field.bool({ default: false }),
  createdAt: field.datetime({ auto: true })   // set on create,
})
export type Post = Infer<typeof Post>
```

```bash
pnpm tvine makemigrations && pnpm tvine migrate
```

Fields: `id uuid text int float bool decimal money datetime date time email url slug phone json enum tags fk m2m
file image richText encryptedText` and more. Options: `default optional unique index searchable hidden readOnly humanOnly`.
For a foreign key: `author: field.fk(() => Author, { onDelete: 'cascade' })` (the row gets `authorId`).
For the user: `field.fk(getUserModel)`, imported from `tvine/auth`.
ORM: `Post.objects.filter({ published: true, title__contains: 'x' }).order('-id')`, `.first()`, `.count()`,
`Post.get(id)`, `Post.create({...})`, `qs.update({...})`, `qs.delete()`.

### 2. Views: ListView / DetailView + @action

```ts
// apps/blog/views.ts
import { z } from 'zod'
import { action, defineAction, DetailView, ListView, loginRequired } from 'tvine'
import { Post } from './models.ts'

const idParam = z.object({ id: z.number().int() })
type IdParam = z.infer<typeof idParam>

export class PostList extends ListView<Post> {      // -> blog.list  (?q= search, ?sort=, cursor pages)
  model = Post
  searchFields = ['title']
  filters = ['published']
  ordering = ['id', 'title']
  getQueryset() { return Post.objects.order('-id') }
}

export class PostDetail extends DetailView<Post> {  // -> blog.get  ({ id })
  model = Post

  @action(idParam, { permissions: [loginRequired] }) // -> blog.publish
  async publish({ id }: IdParam) {
    return { updated: await Post.objects.filter({ id }).update({ published: true }) }
  }
}

const addParams = z.object({ title: z.string().trim().min(1).max(200), body: z.string().default('') })
export const add = defineAction('add', addParams, async (p) => ({ post: await Post.create(p) }))   // -> blog.add
```

Other generic views: `CreateView UpdateView DeleteView ListCreateView RetrieveUpdateDestroyView ModelViewSet`.
DRF hooks: `getQueryset(ctx)`, `performCreate`, `getObject`, and so on.
The `ctx` argument (the last one) has `ctx.request.user`, `ctx.request.agent` and `ctx.request.ip`.
`zod` (v3) is a project dependency; import it as `import { z } from 'zod'`.

### 3. URLs (REST paths, optional)

`startapp` already added `path('blog/', include('blog.urls'))` to `config/urls.ts`. Then:

```ts
// apps/blog/urls.ts
import { path } from 'tvine'
import { PostDetail, PostList } from './views.ts'

export const appName = 'blog'
export const urlpatterns = [
  path('posts/', PostList, { name: 'posts' }),                                   // GET  /blog/posts/
  path('posts/<int:id>/', PostDetail, { name: 'post' }),                         // GET  /blog/posts/1/
  path('posts/<int:id>/publish/', PostDetail.action('publish'), { name: 'publish' }), // POST
]
```

No leading `/`. Converters: `int str slug uuid path`. Check the result with `pnpm tvine show_urls`.
REST and `/tvine/api/*` calls from scripts or curl need the header `x-tvine-api: 1`; without it they get a 403
`forbidden`. `api.*` sends it for you. For example:
`curl -H 'x-tvine-api: 1' localhost:3000/blog/posts/`, or
`curl -X POST -H 'x-tvine-api: 1' -H 'content-type: application/json' -d '{"params":{"title":"Hi"}}' localhost:3000/tvine/api/blog.add`.

### 4. Admin: list, filter, search

```ts
// apps/blog/admin.ts
import { admin, ModelAdmin } from 'tvine/contrib/admin'
import { Post } from './models.ts'

class PostAdmin extends ModelAdmin {
  listDisplay = ['title', 'published', 'createdAt']
  listFilter = ['published']
  searchFields = ['title']
  str(p: any) { return String(p.title) }
}
admin.site.register(Post, PostAdmin)
```

The admin is served at `/admin`; you don't add a page file for it.

### 5. A page (server component) with api.* and Weft widgets

```tsx
// app/blog/page.tsx
import { connection } from 'next/server'
import { Page } from 'tvine/weft'
import { Card } from 'tvine/widgets'
import { api, must } from 'tvine/api'
import { NewPost } from './new-post.tsx'

type Row = { id: number; title: string; published: boolean }

export default async function Blog() {
  await connection()                                   // render per request, not at build time
  const posts = must(await api.blog.list({})).items as Row[]
  return (
    <Page name="blog" title="Blog">
      <NewPost />
      {posts.map((p) => (
        <Card key={p.id} entity={`post:${p.id}`} label={p.title} data={{ published: p.published }}>
          {p.title}
        </Card>
      ))}
    </Page>
  )
}
```

### 6. A form (client component)

```tsx
// app/blog/new-post.tsx
'use client'
import { useRouter } from 'next/navigation'
import { api } from 'tvine/api'

export function NewPost() {
  const router = useRouter()
  return (
    <form name="new-post" onSubmit={async (e) => {
      e.preventDefault()
      const f = new FormData(e.currentTarget)
      const r = await api.blog.add({ title: String(f.get('title')), body: String(f.get('body')) })
      if (!r.ok) alert(r.message); else { e.currentTarget.reset(); router.refresh() }
    }}>
      <input name="title" required />
      <textarea name="body" />
      <button type="submit">Publish</button>
    </form>
  )
}
```

With `jsxImportSource: 'tvine/weft'` already set in tsconfig, plain `<form>`, `<input>` and `<button>` are
controllable by agents.
`api.*` returns `{ ok: true, data } | { ok: false, code, message }`. `must(r)` unwraps it or throws.
Call `router.refresh()` yourself after a write.
Model-driven forms: `ModelForm` from `tvine/forms`.
Widgets live in `tvine/widgets`: `Button Input Select Table Dialog Tabs Card` and others.

### 7. A background task

```ts
// apps/blog/tasks.ts
import { z } from 'zod'
import { defineTask } from 'tvine/tasks'
import { Post } from './models.ts'

export const notify = defineTask('notify', async ({ id }) => {          // task id: blog.notify
  const post = await Post.get(id)
  return { title: post?.title ?? null }
}, { args: z.object({ id: z.number().int() }) })
```

Queue it from an action with `await notify.delay({ id })`. The job is queued after the request commits.
Run the worker with `pnpm tvine worker`.
Cron goes in `config/tasks.ts`: `beatSchedule = { 'blog.notify': { cron: '0 3 * * *', args: { id: 1 } } }`.
Then run `tvine worker --beat`.

### 8. Permissions and agent guards

```ts
import { z } from 'zod'
import { defineAction, loginRequired, permissionRequired } from 'tvine'
import { Post } from './models.ts'

const id = z.object({ id: z.number().int() })
export const mine = defineAction('mine', z.object({}), async (_p, ctx) => ({ user: ctx.request.user.id }),
  { permissions: [loginRequired], readOnly: true })
export const remove = defineAction('remove', id, async ({ id }) => ({ n: await Post.objects.filter({ id }).delete() }),
  { permissions: [permissionRequired('blog.delete_post')], confirm: { message: 'Delete this post?' }, destructive: true })
export const wipe = defineAction('wipe', z.object({}), async () => ({ n: await Post.objects.delete() }),
  { humanOnly: 'Deletes every post', destructive: true })
```

- `confirm`: the first call answers `confirm_required` with a token, and the second call with `$confirm` runs it.
  In the browser, `api.*` shows the dialog itself. `{ by: 'human' }` means only a person can confirm.
- `humanOnly`: every agent path gets a 403 `human_only`. In the UI, wrap the button with
  `<HumanOnly reason="...">` from `tvine/weft`. The flag on the action is the real guard.
- Also available: `staffMemberRequired`, `userPassesTest(fn)`, `isAuthenticated`, `hasPerm`, `rate: { limit, windowMs }`
  and `mcp: false` (hidden from MCP).
  On a class view, use `permissions = [...]`. On `@action`, use `{ permissions }`.

### 9. Extend the user model (do it before the first migrate)

```ts
// apps/accounts/models.ts   (pnpm tvine startapp accounts)
import { field } from 'tvine'
import { extendUser } from 'tvine/auth'
export const User = extendUser({ phone: field.phone({ optional: true }) }, { requiredFields: ['email'] })
```

```ts
// config/settings/base.ts, inside base: { ... }
auth: { userModel: 'accounts.User' },
```

In code, use `getUserModel()` (from `tvine/auth`), never a direct import.
`authenticate(ctx, { username, password })` returns the user or `null`.
For sign-in by email only, use `defineUserModel(...)`.
Changing `userModel` after the first migrate is an error.

### 10. Custom HTTP middleware

```ts
// config/middleware/timing.ts
import { defineMiddleware } from 'tvine'

export default defineMiddleware({
  name: 'timing',
  processResponse(req, res) { res.setHeader('x-path', req.tvine.path) },
})
```

Next, add `export { default as timing } from './timing.ts'` to `config/middleware/index.ts`.
Then add `'config.middleware.timing'` to `middleware` in `config/settings/base.ts`.
Middleware runs outermost first. `processRequest(req, res)` runs before the view.

### 11. Settings per environment

```ts
// config/settings/prod.ts  (dev.ts works the same way)
import { defineSettings, env } from 'tvine'
import { base } from './base.ts'

export default defineSettings({
  ...base,
  debug: false,
  db: { url: env.str('DATABASE_URL') },        // throws at boot when unset
})
```

- Shared keys go in `base.ts`. Machine-only overrides go in `config/settings/local.ts`, which is a plain object.
- Secrets come from the environment (`.env` in dev): `TVINE_SECRET`, `DATABASE_URL`, `TVINE_ALLOWED_HOSTS`.
- Read env values with `env.str / int / bool / url / json`.
- Every key is listed in the settings guide below.

### 12. A test

```ts
// apps/blog/tests/blog.test.ts
import { execFileSync } from 'node:child_process'
import { mkdtempSync } from 'node:fs'
import { tmpdir } from 'node:os'
import { join } from 'node:path'
import { afterAll, beforeAll, expect, it } from 'vitest'
import { createAgentServer, type AgentServer } from 'tvine'
import { agentClient } from 'tvine/testing'

let server: AgentServer
beforeAll(async () => {
  const url = `file:${join(mkdtempSync(join(tmpdir(), 'blog-')), 'test.db')}`
  execFileSync('node_modules/.bin/tvine', ['migrate'], { env: { ...process.env, DATABASE_URL: url }, stdio: 'ignore' })
  server = await createAgentServer({ settings: { secret: 'k'.repeat(32), logging: 'none', db: { url } }, appsDir: './apps' })
})
afterAll(() => server.close())

it('adds a post as an agent', async () => {
  const c = agentClient(server)
  const { sid } = await c.get('/')
  const r = await c.do('/', 'blog.add', { title: 'Hi' }, { sid })
  expect(r.events[0]).toMatchObject({ kind: 'ok', action: 'blog.add' })
})
```

Run it with `pnpm tvine test`.

## Rules and gotchas

- **Pages never import models.** `app/` and components use `api.*` from `tvine/api` only, and `tvine check` fails
  otherwise. Run `tvine generate` (or keep `tvine dev` running) so `api.blog.*` is typed.
- **Imports** are `tvine`, `tvine/weft`, `tvine/widgets`, `tvine/api`, `tvine/forms`, `tvine/auth`, `tvine/tasks`,
  `tvine/testing` and `tvine/contrib/admin`. **Never `tvinejs`**: that is only the npm name.
  App files import each other as `./models.ts`, with the extension.
- **Every request is one transaction** (Django `ATOMIC_REQUESTS`). If the action throws, everything rolls back.
  Opt out with `rules: { atomic: false }`. In scripts, use `atomic(async () => ...)`.
- **Await reads; writes may skip await.** Building a queryset runs no SQL. `count/first/get/list` need `await`.
  An un-awaited write inside a request still runs before commit. `tvine check` flags an un-awaited read.
- **List every app in `installedApps`.** Project apps go by folder name (`'blog'`), built-ins by `'tvine.<name>'`.
  `startapp` adds the app for you. An unlisted app does not load.
- **Never hand-edit or delete migrations.** Change `models.ts`, then run `makemigrations` and `migrate`.
- **Run `pnpm tvine check`** after each change. It must print `ok`. Then run `pnpm tvine test`.
- **Action ids** are `<app folder>.<name>`. Names are camelCase and unique per app.
  A method on a view class becomes an action only with `@action(schema)`.
- **Params are zod.** Validation runs before your code, so a bad param never reaches it.
  Throw `DomainError` for business errors.
- **Dev server and ports.** `tvine dev` defaults to port 3000 and moves up if that port is busy. Read the printed URL.
  `.mcp.json` assumes 3000, so update it if the port changed. Pick a port with `--port`.
  Pages live at `/`, the admin at `/admin`, MCP at `/mcp`, health at `/tvine/health`.
- **What agents (MCP) see:**
  - every action as a tool `<app>_<name>`, except `humanOnly`, `mcp: false` and patterns in `settings.mcp.exclude`
  - plus `read_page`, `expand`, `ui`, `do`, `request_control` and `release`
  - The scaffold excludes `admin.*`.
  - Fields marked `humanOnly` or `hidden` are not shown to agents.
  - Give widgets a `name` / `entity` so agents get stable ids.
- **Don't edit generated files.** That means `tvine-api.d.ts` and `migrations/*`. Leave `next.config.ts`
  `compress: false` as it is.
